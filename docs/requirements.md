# 需求与验收标准

## 1. 目标

构建一个可以本地运行的跨境电商 BI Agent Demo，验证以下核心假设：

1. 卖家可以使用自然语言查询经营数据；
2. Agent 能把问题转为受限、可审计的 BI 查询；
3. 用户权限、积分和会话由业务后端控制，不交给模型；
4. 模型只接收完成权限过滤后的必要数据；
5. 回答包含查询范围、数据新鲜度、指标和可执行建议；
6. 更换模型厂商不会影响用户、会话和数据体系。

## 2. 用户与场景

目标用户是在 Shopee、TikTok 等平台经营店铺的跨境电商卖家。Demo 使用一个租户、一个用户和三个店铺：

- Shopee 新加坡旗舰店；
- TikTok 泰国直播店；
- Shopee 马来西亚店。

演示数据包含最近 60 天的订单量、销售额、退款量、投诉量和平均响应时长。

## 3. 功能需求

### FR-01 身份与租户

- 业务 API 必须在调用 Agent 前识别用户和租户；
- Demo 通过 `x-demo-user-id` 模拟认证；
- Agent 不能接受模型生成的 `user_id` 或 `tenant_id`。

### FR-02 店铺权限

- 每次 Agent Run 创建短期权限快照；
- BI 查询只接受 `permission_snapshot_id`；
- BI 服务必须在服务端解析允许访问的店铺；
- 模型不能指定未授权店铺。

### FR-03 套餐积分

- 请求开始前预占积分；
- 成功后按实际使用量结算并释放余额；
- 失败或取消后退回预占积分；
- Agent 只能上报用量，不能修改账户余额。

### FR-04 会话与历史记录

- 业务后端创建和管理 `conversation_id`；
- 用户消息在调用 Agent 前持久化；
- 最终回答收到 `answer.completed` 后持久化；
- 中途流式文本不能直接作为完成消息；
- 历史消息与结构化 BI 状态分开保存。

### FR-05 Agent Run

- 每次提问创建独立 `run_id`；
- Agent 服务以 NDJSON 返回运行事件；
- 前端可以看到意图、权限、查询、分析和渲染阶段；
- 用户可以取消正在执行的 Run；
- Run 必须以 `answer.completed` 或 `run.failed` 结束。
- 每次模型尝试必须记录实际 Model Profile、Prompt 版本、模型和配置 Hash；
- 切换备用模型时必须加载备用模型自己的完整 Profile。

### FR-06 BI 查询

MVP 支持：

- 最近 7 至 90 天经营概览；
- 单维度店铺退款率排名；
- 每日销售额趋势；
- 店铺客服响应时长排名；
- 店铺投诉量分析。

查询计算由 BI 服务完成，Agent 不重新计算业务指标。

### FR-07 结构化回答

回答必须包含：

- 回答类型和标题；
- 简明结论；
- 查询时间、店铺、平台、时区、币种和数据新鲜度；
- 核心指标卡片；
- 受限图表 Schema；
- 数据依据；
- 建议、优先级和验证指标；
- 局限说明和后续问题。

### FR-08 错误处理

至少区分：

- 未登录；
- 权限失效；
- 积分不足；
- BI 查询失败；
- Agent 服务不可用；
- 模型配置缺失；
- 用户主动取消；
- 流式响应未正常结束。

### FR-09 Agent Eval

- 评测集必须有独立 ID、版本和发布状态；
- 案例必须同时定义最终结果和 Tool 轨迹预期；
- Eval Run 异步执行，不写用户会话历史、不扣套餐积分；
- 结果必须保存逐项断言、最终回答、模型 Attempt 和 Tool Trace；
- 后台必须展示配置、评测集、运行结果和单案例详情；
- 已发布评测集不能通过后台直接覆盖，变更通过新版本表达。

## 4. 业务规则

- 默认查询最近 30 天，数据截至昨日；
- 单次查询最多 90 天，最少 7 天；
- 金额使用用户报表币种，Demo 固定为 SGD；
- 订单量保持整数，金额、比例和响应时长分别格式化；
- 不展示模型内部思考过程，只展示分析依据；
- 退款、投诉和响应问题只形成待验证假设；
- 原始经营数据和数据库凭证不能传给模型；
- 买家消息等不可信文本不能直接改变工具参数或系统指令。

## 5. 非目标

当前不实现：

- 多租户生产认证；
- 多币种历史汇率换算；
- 原始订单或消息明细查询；
- 多维任意钻取；
- 预测模型；
- 行业基准对比；
- 自动修改店铺、商品或客服配置；
- 生产级数据仓库与流处理；
- 模型微调。

## 6. 验收标准

### 本地运行

- `npm install` 成功；
- `npm run db:seed` 能重复生成演示数据；
- `npm run dev` 同时启动三个应用；
- 无模型密钥时可以完成全部演示场景。

### 数据与权限

- 所有 BI 查询只能返回权限快照中的店铺；
- 前端不能通过修改请求体扩展店铺范围；
- 回答数值与 SQLite 聚合查询一致；
- 查询范围和数据最新时间始终可见。

### 会话与积分

- 刷新页面后仍能查看已完成回答；
- 成功请求按用量结算；
- 失败与取消请求退回积分；
- `conversation_id`、`run_id` 和模型厂商 ID 互不混用。

### 工程质量

- TypeScript 严格模式通过；
- 单元测试通过；
- 所有 Workspace 可以构建；
- 共享 API 数据必须经过 Zod Schema 校验。
- Model Profile 和 Prompt 必须版本化，历史 Run 可以追溯到实际配置。
